# 범어네거리 통합 및 화면 구성

## 변경 범위

기존 Streamlit 앱에 ‘대구 범어네거리’를 추가했다. 지도·궤적, 실험 결과, 계산 기준·검증, 시각화 자료의 네 화면으로 구성한다. 기존 공식 계산, SUMO 실행, 후보 탐색, 기본 교차로 재생, 심화 연구를 유지한다. 계산 모델 자체나 저장된 기존 실험 수치는 변경하지 않았다.

화면은 CARTO Builder의 공간 분석 작업 구성을 참고해 왼쪽 탐색, 지도와 데이터 작업 영역, 간결한 도구막대로 통일했다. 흰색·회청색 표면, 남색 본문, 파란색 동작 강조와 Pretendard Variable v1.3.9를 적용했다. 차트의 입주 전은 회색, 입주 후는 황토색, 조정안은 파란색이다. CARTO의 브랜드나 로고를 사용하지 않는다.
참고: https://docs.carto.com/carto-user-manual/maps
폰트 출처와 라이선스: https://github.com/orioncactus/pretendard / static/fonts/OFL.txt

## 원본과 연결 방식

별도 traffic-impact-visuals-daegu 프로젝트는 보존했다. 92개 파일을 case_studies/daegu_beomeo/v1로 바이트 단위 복사하고 import_manifest.json에 SHA-256을 기록했다. 원본 그래프 10종, 비교 영상, SUMO XML·FCD·신호 기록을 보존했다. 별도 derived_metrics.json에서 차량 집단을 다시 집계한다. 실행 내역 목록 experiments/comparison.json에는 넣지 않아 기본 교차로 후보 탐색과 섞이지 않는다.

브라우저는 같은 8502 앱의 static/daegu JSON을 사용한다. 독립 갤러리 서버가 필요하지 않다. 지도 컴포넌트는 화면 이탈 시 애니메이션·관찰자·요청을 종료한다. 기본 입력은 scenario_config에 보존하고 도시 화면에서는 기본 모델 입력을 숨겨 잘못된 연동을 방지한다.

## 지표와 계산 대상

전체 집단: 0 ≤ 예정 출발 < 1,500초. 관측 예정 집단: 300 ≤ 예정 출발 < 1,500초. 실제 진입 시각이 아닌 예정 시각으로 집단을 고정한다. 최종 상태는 2,100초에 집계한다. 요청 = 완료 + 도로 안 미완료 + 도로 밖 미진입이다. timeLoss와 waitingTime 평균은 해당 집단 중 완료한 차량만 분모에 넣는다. 미완료·미진입을 0초로 치환하지 않는다.

전체 집단의 요청/완료/미완료/미진입:
- 입주 전: 1105 / 1058 / 47 / 0
- 입주 후: 1355 / 1086 / 146 / 123
- 조정안: 1355 / 1173 / 143 / 39

관측 예정 집단의 요청/완료/미완료/미진입:
- 입주 전: 884 / 837 / 47 / 0
- 입주 후: 1084 / 815 / 146 / 123
- 조정안: 1084 / 902 / 143 / 39

입주 후→조정안 완료 평균 timeLoss는 전체 집단 193.62→197.76초, 관측 예정 집단 208.00→224.86초다. 완료 수 +87대와 함께 보되 완료 차량 구성이 달라져 선택 편향이 남는다. 모든 상황에서 미완료가 남으므로 최적안으로 선정하지 않는다.

평균 정지 차량은 [300,1500)에서 2초 간격으로 네트워크 전체의 속도 <0.1m/s 차량을 센 산술 평균이다. 차량 집단 선택과 독립적이다. 입주 후 135.04대→조정안 119.47대. 대기행렬 길이나 공식 지체시간이 아니다.

도로 평균속도는 Σ(speed×sampledSeconds)/ΣsampledSeconds×3.6이다. 도로 누적 정지는 edgeData waitingTime 합/60 (차량·분)이다. 재생 지도는 3개 상황 공통 색 범위를 쓴다. 정지 지도 색을 시나리오마다 다른 최대값으로 정규화하던 원본 방식은 통합 화면에서 수정했다. 원본 이미지 파일은 수정하지 않았으므로 원본과 통합 지도 스타일은 다를 수 있다.

재생은 300..1496초의 4초 간격 위치·속도·신호를 표시한다. 순간 차량 수와 기간 평균을 구분한다. 2.5D 건물은 OSM 평면에 태그 높이 또는 높이 가정을 적용한 별도 렌더러다. 898개 중 699개는 12m를 가정했다. SUMO 자체 3D나 측량 모형이 아니다.

## 검증 범위

기존 기본 교차로의 보행 형상·횡단시간 검사와 다중 시드 후보 검증은 그 기본 모델에만 적용된다. 범어네거리는 합성 수요 시드 2026, 단일 녹색 배분 후보이며 보행 시뮬레이션·횡단시간·현장 차로·회전·신호·수요 보정을 수행하지 않았다. 원본 구조 검사 23개는 자료 보존, 수요 일치, 차량 수 보존, 신호 기록·좌표 등 구조 검증이다. 충돌·순간이동 0은 해당 실행의 사건 집계이며 교통안전 검증을 뜻하지 않는다. 공식 LOS를 제시하지 않는다.

통합 검사는 원본 해시, 원시 tripinfo로부터 재집계, 집단 경계, 미완료 처리, 집단별 표·차트 일치, 도시 화면의 무실행·독립성, 화면 이동 후 입력 복원과 기존 회귀 검사를 포함한다. 실제 SUMO 빠른 실행, 차량·보행 신호 동작, 동일 수요, 후보 탐색·취소·이어 실행·별도 시드 검사는 pytest에서 실행한다. 상세 결과는 integration_tests.xml을 확인한다.

검사 중 발견·수정: 원본 평균은 소수 둘째 자리로 저장되므로 원시 재집계와 비교 시 동일 반올림 정밀도로 비교했다. Windows 기본 cp949 환경에서 기존 취소 상태 테스트가 UTF-8 상태 파일을 읽지 못하는 문제를 명시적 UTF-8 읽기로 수정했다. 수치 모델 변경은 없다.

전체 자동 검사 90개를 통과했다(68.30초). 마지막 화면·차트 조정 후 관련 18개도 통과했다(13.60초). 브라우저에서는 4개 지도 방식, 시나리오 선택, 재생·정지·시각 이동·확대·차량 선택, 집계 기준 변경, 기존 두 화면 궤적 재생을 확인했다. PNG 다운로드를 원본 해시와 대조했고 비교 영상 25초가 로드되는 것을 확인했다. 브라우저 콘솔 오류는 관측되지 않았다. 증거는 integration_browser_check.json과 integration/에 저장했다. ZIP 복사 경로 검증은 release_extraction_v3.json에서 별도 확인한다.

## 개발 도구와 활용 범위

도시 사례 통합과 UI는 AI 개발 도우미를 활용해 구현했다. 기획·개발에는 외부 지원이 포함되어 있으며 사용 도구와 지원 범위는 contributions.md에 정리했다. 현장 조건과 합성 수요의 차이, 완료 집단의 변화, 미완료 처리 범위는 별도 검토 대상이다. 실제 신호 운영·안전 판단·공식 교통영향평가용 검증은 미실시 상태다.
