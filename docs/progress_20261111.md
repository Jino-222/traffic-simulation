- 16개 합성 시나리오. 시간대 수요와 차종 비율을 UI에서 적용.
- 결과 카드, 방향별 변화, 완료 상태, 수요/용량, 정지 시계열, 누적곡선, 분포, 시간 히트맵, 신호 타임라인.
- 후보 탐색에서 기준 실험 누락·실패·미완료를 제외. 같은 수요 파일 확인. 재사용·중단·이어 실행·실패 재시도 테스트.
- 전체 평균 우선/최악 방향 우선 추천, 악화 상한 필터, 후보 곡선·절충 그래프·시드별 차이.
- 후보를 고정한 뒤 별도 시드로 평가하는 holdout 모듈.
- 실제 궤적을 120초 단위 파일로 읽는 웹 재생. 재생/정지/배속/시간 이동/확대/차량 선택/두 상황 같은 시각/정지 차량 시계열 커서.
- 브라우저에서 930초 및 1200초의 실제 표시를 확인. 1200초 경계에서 이전 구간의 1199.5초 프레임을 선택하던 오류를 수정하고 양쪽 1200.0초 기록을 확인.
- 전체 회귀 테스트 71개 통과(docs/tests_v2.xml), 이후 정지 차량군 계산 테스트 2개 추가 통과. 마지막 UI/그래프/정지 차량군 관련 11개 통과(docs/visual_tests_v2.xml).
- AppTest가 __main__ 모듈을 바꿔 Windows 다중 프로세스 테스트가 앱을 재실행하던 테스트 격리 오류 수정. 실패 XML은 docs/tests_failure_apptest_spawn.xml 보존.

## E2 대기행렬 독립 검증에서 발견한 차이

scripts/audit_e2.py의 정지 차량 배치 실험:
- 첫 차로: 길이 25m와 15m인 분리된 정지 차량군. E2 반환값 165m.
- 둘째 차로: 연속 차량군 길이 29m. E2 반환값 29m.
- 차량별 앞·뒤 위치를 직접 대조했습니다. 차로 변경을 허용한 초기 잘못된 실험도 별도 보존했습니다.
- SUMO 1.28.0의 getJamLengthMeters는 내부 jam 길이 합계에 연결되므로 '단일 최장 대기행렬'로 읽으면 안 됩니다.
- 분리된 정지 차량군 사례의 차이가 있어 E2 원자료 길이는 검증 완료 지표로 사용하지 않습니다.
- traffic/queue.py가 FCD 위치·속도에서 '최장 연속 정지 차량군'을 별도 계산합니다. 0.1m/s 미만, 1초 초과 정지, 차간 범퍼 간격 10m 이하를 기본 가정으로 사용합니다.
- 병렬 차로는 최댓값으로 집계하고 합산하지 않습니다. 검지 구간 경계와 궤적 반올림·시간 간격의 한계를 기록합니다.
- 기준 세 상황의 geometric_queue.csv 및 정의 파일을 생성했습니다. 원래 telemetry.csv의 queue_m은 E2 원자료라는 점을 유지합니다.

## 공개 실측 자료

US DOT/FHWA NGSIM Lankershim의 차량 ID·시간 범위를 제한한 26,905행, 49대 표본을 확보했습니다.
metadata.json, request.json, 원본 JSON과 SHA-256, 단위 변환 CSV, ATTRIBUTION.md를 보존했습니다.
피트·피트/초를 미터·미터/초로 바꾸고 결측/중복/시간 간격을 검사했습니다.
동일 차로·구간·방향의 10초 이상 연속 추종 구간을 추출하고 대상 차량 기준 11대 보정/10대 검증으로 분리했습니다.
같은 장소·겹치는 시간대의 편의 표본이며 다른 현장으로의 일반화를 증명하지 않습니다.
매개변수 보정과 별도 검증 실험은 아직 수행 전입니다. 실측 자료와 합성 아파트 수요를 혼합하지 않습니다.
